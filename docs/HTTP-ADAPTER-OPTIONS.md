# HTTP-адаптер: in-process и вариант «как ОС» (процессы)

## Сейчас: один процесс

HTTP-сервер (uvicorn + FastAPI) запускается **в том же процессе**, что и ядро:

- `main()` после `runtime.start()` делает `await server.serve()` в главной корутине.
- Один event loop, один процесс. Ctrl+C выставляет `server.should_exit` → `serve()` выходит → shutdown.
- Сигналы uvicorn отключены (`capture_signals = nullcontext`), чтобы прерывание обрабатывал `main()`.

Порт задаётся через `API_PORT` (по умолчанию 8000).

---

## Идея: HTTP как отдельный процесс («как операционная система»)

Чтобы видеть **отдельный процесс** под HTTP (как отдельный «демон»/сервис), возможны два подхода.

### Вариант A: Прокси-процесс

- **Процесс 1 (ядро):** Core Runtime + внутренний HTTP на `127.0.0.1:8001` (только localhost).
- **Процесс 2 (адаптер):** Лёгкий прокси (nginx, caddy или свой скрипт) на порту 8000, проксирует на `127.0.0.1:8001`.

В итоге два процесса; снаружи обращаются к 8000. Готового кода в репо под этот режим пока нет — нужны флаг/конфиг «слушать только 8001» и отдельный скрипт/конфиг прокси.

### Вариант B: Два процесса с полным рантаймом

- **Процесс 1:** ядро без HTTP (или только внутренний порт).
- **Процесс 2:** тот же код, но режим «только HTTP» — поднимает runtime и только `server.serve()`.

Минус: два полных рантайма в памяти. Плюс: можно реализовать через общий entrypoint и переменную окружения/флаг.

---

## Заготовка под «адаптер = процесс»

Сейчас **готовой реализации** «HTTP только в subprocess» в коде нет. Чтобы её добавить, логичные шаги:

1. Ввести опцию (например, `RUNTIME_HTTP_LISTEN_INTERNAL_ONLY=1`): при старте ядро слушает только `127.0.0.1:8001`.
2. Отдельный скрипт или команда (например, `python -m modules.api.proxy 8000 8001`), которая поднимает HTTP-прокси 8000 → 127.0.0.1:8001.
3. Опционально: `main()` при флаге вроде `RUNTIME_HTTP_AS_SUBPROCESS=1` сам запускает этот прокси через `subprocess`, чтобы снаружи был один entrypoint, но в списке процессов видно два (ядро + прокси).

Execution layer уже умеет запуск операций в subprocess (`core/execution/backends/process.py`, `ProcessBackend`) — это про выполнение операций, не про HTTP-адаптер.
